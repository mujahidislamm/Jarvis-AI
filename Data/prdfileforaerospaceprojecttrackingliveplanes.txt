## 1. Executive Summary  

Aerospace operators, regulators, and enthusiasts increasingly demand real‑time visibility of aircraft movements for safety, operational efficiency, and situational awareness. This project delivers a **Live Plane Tracking System (LPTS)** that ingests ADS‑B, MLAT, and radar feeds, correlates them, and exposes a secure API and UI for stakeholders to view, analyze, and act on live flight data.

---

## 2. Problem Statement  

- **Fragmented Data Sources** – ADS‑B receivers, radar sites, and satellite feeds are scattered, each with its own format and latency.  
- **Latency & Accuracy Gaps** – Current consumer solutions lag behind real‑time by 1‑5 seconds and suffer from position inaccuracies.  
- **Limited Scalability** – Existing tools struggle to handle thousands of concurrent streams during peak traffic periods.  
- **Insufficient Analytics** – Operators lack integrated tools for anomaly detection, flight‑plan deviation alerts, and historical trend analysis.

## 5. Key Features  

| Feature | Description | Priority |
|---------|-------------|----------|
| **1. Multi‑Source Ingestion** | Real‑time ingestion of ADS‑B, MLAT, radar, and satellite streams. | Must |
| **2. Data Normalization & Correlation** | Convert all feeds into unified flight objects, deduplicate, and resolve conflicts. | Must |
| **3. Low‑Latency Storage** | Use time‑series DB (e.g., InfluxDB) + in‑memory cache (Redis) for fast reads. | Must |
| **4. Web & Mobile UI** | Real‑time map, flight details, alerts, and historical replay. | Should |
| **5. REST & GraphQL API** | Secure endpoints for position, flight status, and analytics. | Should |
| **6. Alert Engine** | Rule‑based alerts: deviation, speed, altitude, conflict. | Must |
| **7. Historical Analytics** | Trend dashboards, anomaly detection, exportable reports. | Could |
| **8. User & Role Management** | RBAC, MFA, audit logs. | Must |
| **9. Data Export & Integration** | Webhooks, CSV, JSON, and support for third‑party tools. | Could |
| **10. Scalability & HA** | Auto‑scaling, load balancing, multi‑region deployment. | Must |

## 8. Technical Requirements  

| Category | Requirement | Details |
|----------|-------------|---------|
| **Data Ingestion** | Protocols | ADS‑B (UDP), MLAT (TCP), Radar (custom). |
| **Processing** | Language | Java 17 + Akka Streams for back‑pressure. |
| **Storage** | Time‑Series DB | InfluxDB 2.x (retention 30 days) + Redis cache. |
| **API** | Framework | Spring Boot 3.x + GraphQL Java. |
| **UI** | Tech Stack | React 18 + Mapbox GL JS, mobile via React Native. |
| **Security** | OAuth2 + JWT, TLS 1.3, MFA via TOTP. |
| **Deployment** | Cloud | AWS EKS + Fargate, CloudWatch, RDS Aurora. |
| **Observability** | Logging | Elastic Stack; metrics via Prometheus. |
| **Compliance** | GDPR, ISO 27001 | Data retention policy, audit logs. |
