### The Two‑Sum Problem

> **Problem statement** – Given an array of integers `nums` and an integer `target`, return the indices of the two numbers that add up to `target`.  
> Each input will have *exactly one solution*, and you may not use the same element twice.

---

### A Clean, Pythonic Solution

Below is a straightforward implementation that uses a **hash table** (Python’s built‑in dictionary) to keep track of the numbers we’ve seen so far. The algorithm runs in linear time, O(n), and uses O(n) additional space.

```python
def two_sum(nums, target):
    """
    Find indices of the two numbers in `nums` that add up to `target`.

    Parameters:
        nums   (List[int]): List of integers.
        target (int)      : The desired sum.

    Returns:
        List[int]         : A list containing the two indices.
    """
    # Map each number to its index as we iterate
    seen = {}
    for i, num in enumerate(nums):
        complement = target - num
        # If the complement is already in our map, we found a pair
        if complement in seen:
            return [seen[complement], i]
        # Otherwise, remember this number's index
        seen[num] = i

    # According to the problem statement, this line is never reached,
    # but it’s good practice to raise an informative error.
    raise ValueError("No two sum solution found.")
```

#### How It Works

1. **Initialize** an empty dictionary `seen`.  
2. **Iterate** over `nums` with `enumerate` to keep track of both the index (`i`) and the value (`num`).  
3. **Compute** the `complement` that would sum with `num` to reach `target`.  
4. **Check** if the `complement` is already in `seen`.  
   - If yes, we’ve found the pair: return the stored index and the current index.  
5. **Store** the current number and its index in `seen`.  
6. **Continue** until the loop ends.  
7. If no pair is found (which shouldn’t happen given the problem’s guarantees), raise an error.

### Why This Approach Is Elegant

- **Time‑Efficient** – Each element is examined once; dictionary look‑ups are O(1).  
- **Space‑Efficient** – We only store each element once in the dictionary.  
- **Readable** – The logic flows naturally from “look for the complement” to “store what we’ve seen”.
